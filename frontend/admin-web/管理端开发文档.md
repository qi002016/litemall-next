## 二、通用约定（先落地这层，后面所有页面照抄）

### 2.1 请求封装 `utils/request.js`

统一返回结构（后端 `Result`）：



```
{ "code": 200, "msg": "成功", "data": {} }
```



* baseURL：开发期走 Vite 代理 `/admin` → `http://localhost:8000/admin`；生产同域。

* 请求头自动带 `Authorization: Bearer <token>`（从 pinia/localStorage 读）。

* 响应拦截：


  * `code === 200` → 返回 `data`；

  * `code === 401` → 清 token、跳 `/login`；

  * 其他 → `ElMessage.error(msg)` 并 reject。

* 分页接口返回 `PageVO`：`{ total, pages, list }`。

### 2.2 路由与登录守卫



* 除 `/login` 外全部 `meta: { requiresAuth: true }`。

* 无 token → 重定向 `/login?redirect=xxx`。

* 登录成功后跳 `redirect` 或 `/dashboard`。

### 2.3 数据字典（前后端共用）



| 维度    | 取值                                                                                      |
| ----- | --------------------------------------------------------------------------------------- |
| 商品上下架 | `isOnSale` true/false                                                                   |
| 订单状态  | `unpaid` 待付款 / `paid` 待发货 / `shipped` 待收货 / `confirm` 已完成 / `cancel` 已取消 / `refund` 售后中 |
| 优惠券类型 | 满减券 / 折扣券；`timeType` 限时 / 固定天数                                                          |
| 用户状态  | 正常 / 冻结                                                                                 |

> 所有字典统一在 
>
> `utils/dict.js`
>
>  导出 
>
> `options`
>
>  和 
>
> `labelMap`
>
> ，表格列和下拉选项共用。

### 2.4 其他硬约定



* 后端 Long 序列化为字符串（JS 精度），前端不要再 `Number(id)`。

* 金额一律 `BigDecimal`，前端展示 `¥{{ price }}`，不做前端四舍五入。

* 列表页统一三件套：**搜索栏 → el-table → el-pagination**，交互完用 `PageTable` 封装。

* 写操作（增删改 / 上下架）成功后 `ElMessage.success` + 刷新列表。

## 五、通用页面开发范式

### 5.1 列表页（以商品列表为例）



```
\<el-form :inline> 搜索关键词 / 分类下拉 / 上下架下拉 / 查询 / 重置

\<el-table>  图 | 名称 | 分类 | 价格 | 库存 | 上架开关 | 操作(编辑/删除)

\<el-pagination>
```



* 搜索条件变化 → 重置 `pageNum=1` → 重新请求。

* 上下架用 `el-switch` 直接调 `PUT /admin/goods/upshelf`，带 `el-message` 确认。

### 5.2 新增 / 编辑

统一用 `el-dialog` + `el-form`，同一份表单组件 `GoodsForm.vue`，通过 `props.goodsId` 区分新建 / 编辑；打开时若有 id 再拉详情。

### 5.3 图片上传

封装 `ImageUpload.vue`：`POST /admin/storage/upload`（multipart），回显 URL；商品轮播图支持多张。

### 5.4 富文本

商品详情接入富文本编辑器（wangeditor /quill），内容存 HTML。

## 六、推荐开发顺序（迭代）



1. **第 1 周（骨架闭环）**：request 封装、登录联调、AdminLayout 菜单、商品列表、订单列表、用户列表（先只读分页）。

2. **第 2 周（核心写操作）**：商品新建 / 编辑 / 上下架、分类树形 CRUD、订单发货、售后审核。

3. **第 3 周（营销 + 完善）**：广告、优惠券、专题 CRUD；Dashboard 数据看板。

4. **第 4 周（系统 + 打磨）**：管理员 / 角色 / 配置 / 日志，权限按钮级控制、404/401 页。

## 七、联调注意事项



* 网关 `/admin/**` 路由到各业务服务，**管理端 token 走单独的 admin 登录态**，与 C 端 `/app` 不通用。

* 后端写操作会触发 Redis 缓存失效（商品详情 / 分类树），前端无需处理，但改完数据要刷新列表。

* 保留字列（如 coupon 的 `desc/min/limit`）后端已转义，前端按 VO 字段名取值即可。

* Long id 一律当字符串用；分页 `total/pages` 也是字符串展示。

* 启动：`cd admin-web && npm run dev`，默认端口建议 **5174**（与 H5 的 5173 区分）。
