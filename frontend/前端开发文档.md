## 1. 总体说明

新项目前端拆为两个独立工程，统一走网关，统一请求封装与统一响应处理：

| 工程 | 目录 | 形态 | 技术栈 | 开发端口 |
| --- | --- | --- | --- | --- |
| **mobile-web** | `frontend/mobile-web` | C 端 H5 商城（手机浏览器） | Vue 3.5 + Vite 8 + **Vant 4** + Pinia + Vue Router 4 + Axios | 5173 |
| **admin-web** | `frontend/admin-web` | 运营管理后台（PC） | Vue 3.5 + Vite 8 + **Element Plus 2.14** + Pinia + Vue Router 4 + Axios | 5174 |

> 老项目的 `renard-wx` / `litemall-wx` 为微信小程序，本套前端不涉及，沿用老代码。

### 1.1 与老项目的对应关系

| 老项目（litemall-vue, Vant2） | 新项目（mobile-web, Vant4） |
| --- | --- |
| `Vue.use(Router)` + hash 路由 | Vue Router 4 history 路由，`createWebHistory` |
| `vuex` | Pinia（`src/store`） |
| `axios` 拦截器 + `X-Litemall-Token` 头 | Axios 实例 + `Authorization: Bearer {token}` 头 |
| baseURL `/wx` | 统一 `/app/**`（C 端），由 Vite 代理到网关 |
| `errno === 0` 成功 / `501` 未登录 | `code === 200` 成功 / `401` 未登录 |
| views: home/items/login/order/user | 同名页面重写为 `<script setup>` + Vant 4 组件 |

## 4. 接口约定（前端侧硬约束）

### 4.1 统一响应

后端统一返回：`{ "code": 200, "msg": "成功", "data": {} }`

- **成功判定**：`code === 200`。这是 `Result.ok()` 的唯一成功值——后端不存在返回 `code = 0` 的代码路径
  （`Result.success()` 也按 `code == 200` 判定），故请求封装不再兼容 `0`。直接返回 `data`。
- **未登录**：`code === 401` → 清 token、跳登录页并带 `?redirect=`。
- **无权限**：`code === 403` → 提示 `msg`。
- **业务错误**：其余非成功码 → `Toast` / `ElMessage` 提示 `msg` 并 reject。

### 4.2 请求头

| Header | 值 |
| --- | --- |
| `Authorization` | `Bearer {token}`（登录后由拦截器自动注入） |
| `Content-Type` | `application/json`（上传除外） |

### 4.3 分页

GET 列表带 `pageNum`(默认1)、`pageSize`(默认10)、`sort`、`order`；响应 `{ list, total, pageNum, pageSize, pages }`。

### 4.4 接口前缀

- C 端（mobile-web）：`/app/**`
- 管理端（admin-web）：`/admin/**`
- 开发态均由 Vite 代理到网关 `http://localhost:8000`，不带 `/api` 前缀、不 rewrite。

---

## 5. 请求封装规范

`utils/request.js`：请求拦截注入 token；响应拦截按第 4.1 条判定；超时 15s；API 模块只声明 `url+method+params/data`。

## 6. 路由与权限

- mobile-web：`meta.requiresLogin=true`（购物车/下单/订单/地址/我的优惠券）无 token 跳 `/login?redirect=`；TabBar 页：首页 `/`、分类 `/category`、购物车 `/cart`、我的 `/user`。
- admin-web：`/login` 白名单，其余 `meta.requiresAuth=true`；退出清 token 回登录。

## 9. 购物助手（Agent，独立开发阶段）

### 9.1 目标与阶段

C 端买家购物助手，一期为「只读问答」：按预算推荐商品、查询订单 / 物流、找优惠券、售后指引。独立开发完成后整合到商城（入口 + 真实后端）。

### 9.2 目录

| 文件 | 说明 |
| --- | --- |
| `src/views/assistant/AssistantChat.vue` | 聊天页：消息气泡 + 商品/订单/优惠券卡片 + 快捷提问 + 会话持久化 |
| `src/api/agent.js` | 真实接口契约：`POST /agent/session`、`POST /agent/chat`、`POST /agent/session/clear` |
| `src/api/agent-mock.js` | 本地 mock 引擎（意图识别 + 演示数据），与 `agent.js` 同签名，可整体替换 |

路由：`/assistant`（独立页，不挂 TabBar，样式同 `/search`）。

### 9.3 mock 切换

| 环境 | `VITE_AGENT_MOCK` | 行为 |
| --- | --- | --- |
| development | `true`（默认） | 走 `agent-mock.js`，无需后端即可联调 |
| production | `false` | 走 `agent.js` 真实接口 |

接入真实后端时：网关新增 `/agent/**` 路由 → Python LangGraph 服务；Vite 代理已预留 `/agent`。

### 9.4 接口契约（后端对齐目标）

- `POST /agent/session` → `{ sessionId }`
- `POST /agent/chat` body `{ sessionId, message }` → `{ reply, cards? }`
- `POST /agent/session/clear` body `{ sessionId }`
- `cards[]` 元素：`{ type: 'product', items: [{ id, name, brief, price, img }] }` / `{ type: 'order', order: { orderSn, statusText, goodsName, total, time } }` / `{ type: 'coupon', items: [{ id, name, value, desc, expire }] }`

### 9.5 整合步骤（后续）

1. 网关 `RoutePredicate` 加 `/agent/**`，转发到 Agent 服务；
2. 后端实现 `session/chat/clear` 三个接口，字段按 9.4；
3. `Assistant.vue` 中 `onProductClick/onOrderClick/onCouponClick` 恢复真实跳转（代码已留分支）；
4. 商城首页加悬浮入口（`/assistant`）；
5. 生产构建 `VITE_AGENT_MOCK=false`。
