# mobile-agent 接口契约

购物助手 Agent 服务接口契约。前端 `mobile-web` 与网关按本文件对齐。

## 1. 统一信封

所有接口返回 `{ "code": 200, "msg": "成功", "data": {...} }`，与 Java `Result.ok()` / 前端 `utils/request.js` 判定一致（`code === 200` 取 `data`）。

| code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数错误（如 message 为空） |
| 429 | 触发限流（预留） |
| 500 | 服务内部错误 |

## 2. 接口

### POST /agent/session

创建会话。返回 `data: { "session_id": "hex" }`。

### POST /agent/chat

请求体 `{ "session_id": str, "message": str }`。
返回 `data: { "reply": str, "cards": Card[] }`（无卡片时 `cards` 为 `[]`）。

### POST /agent/session/clear

请求体 `{ "session_id": str }`。返回 `data: { "ok": true }`。

### GET /agent/health

返回各层模式：`{ status, llm_provider, tool_fallback, memory }`。

## 3. 卡片数据结构（与前端 agent-mock.js 对齐）

```
product: { "type": "product", "items": [{ "id", "name", "brief", "price", "img" }] }
order:   { "type": "order",   "order":  { "orderSn", "status", "statusText", "goodsName", "total", "time" } }
coupon:  { "type": "coupon",  "items": [{ "id", "name", "value", "desc", "expire" }] }
```

## 4. 鉴权与身份透传

- 前端请求带 `Authorization: Bearer {token}`，网关校验后转发到本服务时透传该头。
- 网关把用户身份写进 **`user-info`** 头（`AuthGlobalFilter` 先剥掉外部伪造的 `user-info` 与内部密钥头，再注入 `user-info: <userId>`）；本服务优先读 `user-info`，读不到才兼容旧的 `X-User-Id`。**早期版本此处写成 `X-User-Id`，与网关实际行为不一致，会让 `user_id` 恒为空、订单与售后工具全部落到「未登录」分支。**
- 本服务在调用 Java 接口时原样转发 `Authorization`，由 Java 侧完成归属校验（Python 不持有/不解析 token）。

## 5. 网关接入

`litemall-gateway/application.yaml` 增加：

```yaml
- id: agent
  uri: http://127.0.0.1:8100        # 未注册 Nacos 时的直连写法
  predicates:
    - Path=/agent/**
```

路径**不剥前缀**（与现有 `/app/**` 一致），Python 服务直接暴露 `/agent/**`。

## 6. 环境开关

| 变量 | 取值 | 说明 |
| --- | --- | --- |
| `LLM_PROVIDER` | `mock` / `ark` | 意图识别与措辞：本地规则 / 火山方舟模型 |
| `TOOL_FALLBACK` | `mock` / `remote` | 工具数据：演示 / Java 网关真实接口 |
| `REDIS_URL` | 空 / `redis://...` | 会话记忆：内存 / Redis |
| `AGENT_HOST` / `AGENT_PORT` | 默认 `127.0.0.1:8100` | 服务监听 |
