> 版本:v1.1 ｜ 更新日期：2026-09-23
> 网关地址:
> `http://{host}:8000`
> (所有外部请求统一走网关)
> 接口风格：RESTful + JSON ｜ 字符编码：UTF-8

> `http://{host}:{port}/doc.html`

> 字段口径：`user_id/order_id` 等外键统一为 `long`；表结构参考老项目 `litemall-master/litemall-db/sql/litemall_table.sql`。

***

## 通用约定

### 统一返回结构

```
{
  "code": 0,
  "msg": "成功",
  "data": {}
}
```

| 字段   | 类型     | 说明               |
| ------ | -------- | ------------------ |
| code   | int      | 0 = 成功；非 0 = 错误码 |
| msg    | string   | 提示信息，可直接展示       |
| data   | any      | 业务数据，失败为 null    |

### 请求头

| Header        | 必填    | 说明                 |
| ------------- | ------- | -------------------- |
| Authorization | 登录后必填 | `Bearer {token}`   |
| Content-Type  | 是      | `application/json` |

### 分页约定

GET 请求带 query 参数:

| 参数       | 类型     | 默认      | 说明          |
| ---------- | -------- | --------- | ------------ |
| pageNum    | int      | 1         | 页码，从 1 开始   |
| pageSize   | int      | 10        | 每页条数，最大 100 |
| sort       | string   | addTime   | 排序字段        |
| order      | string   | desc      | asc/desc    |

分页响应:

```
{
  "list": [],
  "total": 123,
  "pageNum": 1,
  "pageSize": 10,
  "pages": 13
}
```

### 错误码总表

| code | 说明            |
| ---- | ------------- |
| 0    | 成功            |
| 400  | 参数校验失败 / 业务错误 |
| 401  | 未登录或 token 过期 |
| 403  | 无权限 / 账号冻结注销  |
| 500  | 服务器内部错误       |

服务段错误码格式：1xxxx=user, 2xxxx=goods, 3xxxx=marketing, 4xxxx=order, 5xxxx=pay, 6xxxx=message, 7xxxx=storage

### 订单状态字典（4.7 / 4.8 共用）

| 状态码（文档口径） | 含义            | 老项目 order_status |
| ---------------- | ------------- | ------------------ |
| unpaid           | 未付款          | 101                |
| undelivered      | 已付款/待发货    | 102                |
| shipped          | 已发货/待收货    | 201                |
| confirmed        | 已收货/已完成    | 301                |
| refund           | 售后/退款中      | 401/402            |

### Redis 使用约定

> 所有服务已通过 `litemall-common` 聚合 `spring-boot-starter-data-redis`。
> key 统一小写、冒号分隔，形如 `业务:实体:id`；禁止硬编码 TTL，集中到 `RedisKeys` 常量类。

| 场景 | 所在接口 | Key | 数据结构 | TTL | 状态 |
| --- | --- | --- | --- | --- | --- |
| 短信验证码 | 1.3 发送验证码 / 1.2 注册校验 | `captcha:{phone}` | String（6 位码） | 5 分钟；60 秒内禁止重发 | ✅ 已实现 |
| 商品详情缓存 | 2.2 商品详情 | `goods:detail:{id}` | String(JSON)；空值存 `NULL` 占位 | 30 分钟；管理端改商品走"更新 DB → 删缓存 → 延迟 500ms 再删"双删 | 📋 规划（goods 已配连接） |
| 分类树缓存 | 2.3 分类树 | `goods:category:tree` | String(JSON) 全量 | 30 分钟；管理端改分类即删 | 📋 规划 |
| Token 黑名单 | 网关全局（401 拦截） | `auth:blacklist:{jti}` | String(`1`) | 与 token 剩余有效期一致（解析 exp 计算） | 📋 规划：退出登录/改密/冻结时写入 |
| 登录失败限流 | 1.1 登录 | `login:fail:{username}`、`login:fail:ip:{ip}` | String(计数) | 5 分钟；≥5 次拒绝 | 📋 规划 |
| 搜索历史 | 2.7 / 2.8 | `search:history:{userId}` | ZSET（member=关键词，score=时间戳） | 不过期，ZREMRANGEBYRANK 截断最近 10 条 | 📋 规划（替代 MySQL 表） |
| 下单幂等 | 4.6 提交订单 | `order:idem:{uuid}` | String(`1`) SETNX | 5 分钟；提交时 GETDEL，重复提交直接拒 | 📋 规划 |

**明确不使用 Redis 的场景**（避免过度设计）：

- 商品列表（2.1）：categoryId/brandId/keyword/sort 维度组合太多，命中率低；走 DB 索引，后续接 ES。
- 分布式锁 / Redisson：当前无秒杀场景，下单并发用 Seata 分布式事务即可。
- 购物车：以 MySQL 为权威源，不上 Redis。

# 一、user 服务 (端口 8001)

## 1.1 用户登录

* **URL**:`/app/auth/login`
* **Method**:`POST`
* **鉴权**: 白名单
* **限流**: 连续失败 5 次锁定 5 分钟（`login:fail:{username}` / `login:fail:ip:{ip}`）

**请求体:**

| 字段       | 类型     | 必填 | 说明               |
| ---------- | -------- | ---- | ------------------ |
| username   | string   | 是  | 用户名              |
| password   | string   | 是  | 密码 (明文，HTTPS 传输) |

**请求示例:**

```
{ "username": "zhangsan", "password": "123456" }
```

**响应 data:**

| 字段       | 类型     | 说明        |
| ---------- | -------- | --------- |
| userId     | long     | 用户 ID     |
| username   | string   | 用户名       |
| token      | string   | JWT token（RS256，无状态；登出/改密后走黑名单失效） |

**响应示例:**

```
{
  "code": 0,
  "msg": "成功",
  "data": { "userId": 1, "username": "zhangsan", "token": "eyJhbGci..." }
}
```

***

## 1.2 用户注册

* **URL**:`/app/auth/register`
* **Method**:`POST`
* **鉴权**: 白名单
* **Redis**: 校验 `captcha:{mobile}`，通过即 DELETE（一次性防重放）

**请求体:**

| 字段       | 类型     | 必填 | 说明          |
| ---------- | -------- | ---- | ----------- |
| username  | string   | 是  | 用户名 (唯一)    |
| password  | string   | 是  | 密码          |
| mobile    | string   | 是  | 手机号，11 位    |
| code      | string   | 是  | 短信验证码 (6 位) |

**请求示例:**

```
{
  "username": "zhangsan",
  "password": "123456",
  "mobile": "13800138000",
  "code": "123456"
}
```

**响应:** 同 1.1 登录（自动登录并返回 token）。

***

## 1.3 发送短信验证码

* **URL**:`/app/auth/captcha`
* **Method**:`POST`
* **鉴权**: 白名单
* **Redis**: 生成 6 位码写入 `captcha:{phone}`；key 仍在且剩余 TTL > 4 分钟则拒绝（60 秒重发限制）

**请求体:**

| 字段    | 类型     | 必填 | 说明                     |
| ------- | -------- | ---- | ---------------------- |
| phone   | string   | 是  | 手机号，正则 `^1[3-9]\d{9}$` |
| type    | string   | 是  | register / login       |

**请求示例:**

```
{ "phone": "13800138000", "type": "register" }
```

**响应 data:** 固定字符串 `"发送成功"`。重发过于频繁时返回 `code=400, msg="验证码发送过于频繁,请 60 秒后再试"`。

***

## 1.4 微信小程序登录

* **URL**:`/app/auth/wx-login`
* **Method**:`POST`
* **鉴权**: 白名单

**请求体:**

| 字段        | 类型     | 必填 | 说明                   |
| ----------- | -------- | ---- | -------------------- |
| code        | string   | 是  | `wx.login()` 返回的临时凭证 |
| nickname    | string   | 否  | 用户昵称                 |
| avatarUrl   | string   | 否  | 头像 URL               |
| gender      | int      | 否  | 0 = 未知，1 = 男，2 = 女   |

**请求示例:**

```
{
  "code": "0a1BcD2eF3gH4iJ5kL6mN7oP",
  "nickname": "张三",
  "avatarUrl": "https://thirdwx.qlogo.cn/xxx",
  "gender": 1
}
```

**响应:** 同 1.1 登录，新用户自动注册。

# 二、goods 服务 (端口 8002)

## 2.1 商品列表

* **URL**:`/app/goods/list`
* **Method**:`GET`
* **鉴权**: 白名单
* **缓存策略**: 不做整体缓存（维度组合多），走 DB 索引；热点后续切 ES。

**Query 参数:**

| 参数         | 类型     | 必填 | 说明               |
| ---------- | -------- | ---- | ---------------- |
| categoryId | long     | 否  | 分类 ID            |
| brandId    | long     | 否  | 品牌 ID            |
| keyword    | string   | 否  | 搜索关键词            |
| pageNum    | int      | 否  | 页码               |
| pageSize   | int      | 否  | 每页条数             |
| sort       | string   | 否  | 排序:addTime/price |
| order      | string   | 否  | asc/desc         |

**响应 data:** 分页对象，list 元素字段:

| 字段       | 类型      | 说明    |
| ---------- | --------- | ----- |
| id         | long      | 商品 ID |
| name       | string    | 商品名  |
| brief      | string    | 简介    |
| picUrl     | string    | 主图    |
| minPrice   | decimal   | 最低价格  |

***

## 2.2 商品详情

* **URL**:`/app/goods/detail`
* **Method**:`GET`
* **鉴权**: 白名单
* **Redis**: 先查 `goods:detail:{id}`；miss 查 DB 后回填，空结果存 `NULL` 占位 2 分钟防穿透；管理端改商品触发延迟双删。

* **Query 参数**:`id`(long, 必填)

**响应 data:**

| 字段           | 类型        | 说明       |
| -------------- | ----------- | -------- |
| id             | long        | 商品 ID    |
| name           | string      | 名称       |
| brief          | string      | 简介       |
| picUrl         | string      | 主图       |
| gallery        | string[]    | 轮播图      |
| detail         | string      | 详情 (富文本) |
| price          | decimal     | 价格       |
| stock          | int         | 库存       |
| specList       | array       | 规格列表     |
| commentCount   | int         | 评论数      |

specList 元素：

| 字段      | 类型      | 说明           |
| --------- | --------- | ------------- |
| id        | long      | 规格项 ID（即 productId） |
| specText  | string    | 规格描述，如 "颜色:黑;尺码:L" |
| price     | decimal   | 该规格价格       |
| stock     | int       | 该规格库存       |

***

## 2.6 发表商品评论

* **URL**:`/app/goods/comment/post`
* **Method**:`POST`
* **鉴权**: 需登录

**请求体:**

| 字段      | 类型        | 必填 | 说明     |
| --------- | ----------- | ---- | ------- |
| goodsId   | long        | 是  | 商品 ID  |
| content   | string      | 是  | 评论内容   |
| star      | int         | 是  | 评分 1-5 |
| picUrls   | string[]    | 否  | 评论图片   |

**响应 data:** 新建评论的完整 CommentVO（同 2.5 元素字段）。

***

## 2.7 搜索历史

* **URL**:`/app/search/history`
* **Method**:`GET`
* **鉴权**: 需登录
* **Redis（规划）**: 从 `search:history:{userId}` ZSET 取 `ZREVRANGE 0 9`，返回关键词数组；不再读 MySQL `litemall_search_history` 表。

**响应 data:** string 数组，按最近搜索时间倒序，最多 10 条。示例：

```
{ "code": 0, "msg": "成功", "data": ["连衣裙", "T恤", "运动鞋"] }
```

***

## 2.8 清空搜索历史

* **URL**:`/app/search/clear`
* **Method**:`POST`
* **鉴权**: 需登录
* **Redis（规划）**: `DEL search:history:{userId}`；同时清理 MySQL 历史表（过渡期双清）。

**响应 data:** `null`。

***

# 八、管理后台接口 (/admin/**)

管理后台接口与 C 端结构一致，路径前缀改为 `/admin/`, 额外增加分页查询、增删改接口。主要管理域:

| 模块   | 主要接口                               |
| ---- | ---------------------------------- |
| 商品管理 | 商品 CRUD、分类 CRUD、品牌 CRUD、规格管理       |
| 订单管理 | 订单列表、发货、退款审核                       |
| 用户管理 | 用户列表、冻结 / 解冻、详情                    |
| 营销管理 | 广告 CRUD、优惠券 CRUD、团购活动 CRUD、专题 CRUD |
| 系统管理 | 配置管理、管理员账号、角色权限、操作日志               |

管理端写操作（商品/分类/优惠券上下架）须同步触发 Redis 失效：

- 修改/删除商品 → `DEL goods:detail:{id}` + 延迟双删
- 修改/删除分类 → `DEL goods:category:tree`
- 用户冻结/注销 → 将其现有 token jti 写入 `auth:blacklist:{jti}`

具体接口参数与 C 端类似，后续按需补充。
