## 3. 关键实现口径

- **金额**：全部走 `utils/format.js`（`money()` 分→`¥x.xx`、`fen2yuan()`、`yuan2fen()`），前端不做四舍五入；品牌最低价按元录入、提交时转整数分。
- **ID**：一律当字符串处理（BigInt JSON 字符串），不做 `Number`/`parseInt`。
- **错误展示**：写操作用 `{ silent: true }` 关闭全局 toast，失败文案落页内 `.alert err` 错误条，确保「请先移走商品」「品牌名已存在」「内容已被他人修改，请刷新后重试」等后端原文逐字可见（验收 §6.2 第 8 步据此判定）。
- **CAS**：公告更新回传后端原始 ISO `updateTime`（不经 `fmtTime` 格式化），否则 LocalDateTime 反序列化失败。
- **日期筛选**：评价 `dateFrom/dateTo` 后端严格解析 `yyyy-MM-dd HH:mm:ss`，前端 `daterange` 取 `YYYY-MM-DD` 后补 ` 00:00:00` / ` 23:59:59`。
- **URL 状态**：五个页面（含工作台 period）的筛选与分页均进 URL，刷新/分享/前进后退可还原；搜索变化重置 `pageNum=1`。

## 4. 披露与偏差

1. **客单价空值显示「—」而非 0**（captain 裁决确认，保持现状不改）：求和/计数值（GMV、退款金额、订单数）空集为 0，**派生值（客单价、退款率）分母为 0 时后端返回 null、前端显示「—」**，不得显示 0/NaN（口径卡 §2.1.2）。前端与后端口径一致；其余数字缺失按 0 兜底，页面无 NaN/undefined（报表口径说明中也写明了这一点，便于验收核对）。
2. **分类编辑无 CAS，并发覆盖为已知限制**（captain 裁决：接受，本期不补后端出参）：`CategoryAdminVO` 出参不含 `updateTime`，前端无法回传版本，故分类编辑走普通更新，两名管理员同时编辑同一分类时后者覆盖前者；分类的重名/父子/在用冲突仍有唯一键与业务校验 409 兜底，验收 §6.2 八步不含分类并发场景。`keywords`/`desc` 同样无出参，编辑弹窗这两项留空即「不修改」（弹窗内已标注）。品牌/公告有 `updateTime`，CAS 正常生效。
3. **商品编辑弹窗改用 admin 数据源**：`GoodsEditDialog.vue` 原用 C 端 `/app/goods/category`，该接口只返回「自身或子分类下存在在售商品」的分类，导致验收 §6.2 第 1 步新建的空分类在第 2 步选不到；已改用 `/admin/category/list` 与 `/admin/brand/list`（旧 `api/goods.js` 的 `categoryTree/brandList` 保留未删，仅此弹窗不再使用）。
4. **公告无删除**：按后端契约停用即 `enabled=false`，页面只提供启用/停用，无删除入口（页面副标题已说明）。
5. **菜单**：`05-R2实施口径.md` §7 若写「分类品牌挂在商品页内」，本实现按任务书要求独立成页（`/category`、`/brand`），端点路径不变。
