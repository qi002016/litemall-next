## 6. 文档与代码偏差（§0.6 协议登记）

1. **C 端演示账号密码**：需求书 §2.6 写 `user123/123456`，实测 `123456` 登录失败。真实原因是 R4-MQ 自测期间为跑端到端把 `user123` 的密码哈希临时改成了 `r2demo_admin` 的（`admin123`），验收后又误留在库里。**2026-11-07 已从 `.dbwork/backup-20261101-135455.sql` 恢复原始哈希，该账号真实口令是 `user123`**（用户名=密码），需求书 §2.6 与 §14 已同步更正。
2. `litemall_ad.link` 是 `varchar(255) NOT NULL`，需求书 §7.6 的 `link = NULL` 会报错，迁移脚本已改为 `link = ''`（语义不变）。
3. `litemall_topic.goods` 实测是 JSON 数组串 `["993005",...]` 而非需求书所述逗号分隔串；`TopicServiceImpl.parseGoodsIds` 已兼容两种形状。
4. `CollectVO.price` 用 `Integer`（§6.3 定义），JSON 出参为数字 `7900` 而非 §6.4 示例的字符串；前端 `Number()` 兼容两者，未改。
5. `PageVO.total/pages` 为 Long，经全局 ToStringSerializer 输出字符串（§3.2 契约内行为）。
6. `POST /app/market/coupon/receive` 缺 `couponId` 时返回 500 而非 400（`CouponReceiveDTO.couponId` 无 @NotNull）——本期未修，建议后续补参数校验。
7. 需求书 §16.17 的「前端 2 条历史 eslint error」为特定规则口径；全仓 `eslint .` 实测 26 errors / 8 warnings（含 scripts/*.mjs），本期改动前后计数一致，新增 0。
8. `.env` 原 `MALL_BASE_URL=http://localhost:8000` 与 §16.6 冲突、`RATE_LIMIT_PER_MIN` 与代码读取的 `RATE_LIMIT` 不一致——均已修正为 `127.0.0.1` 与 `RATE_LIMIT`。
