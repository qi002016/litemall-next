## 2. 硬要求落点

1. **立即关单二次确认**：`src/views/order/closeOrder.js::closeOrderFlow()` — 先以 `silent` 拉订单详情统计锁定件数，
   再 `ElMessageBox.confirm`（标题「关闭订单 {orderSn}」、按钮「立即关单」/「取消」、danger 样式），
   文案与原型一致（释放锁定库存 N 件、优惠券退回不延长有效期、只影响当前订单），确认后才调用
   `POST /admin/order/close`。订单列表行操作与详情抽屉底部共用同一函数，不存在绕过路径。
2. **库存三量 + 低库存标黄**：`src/views/stock/StockList.vue` 列 `number`（可编辑，失焦/失步提交）、`locked`、`sellable`；
   `sellable<=0` 标红「缺货」、`1..5` 标黄「低库存」（阈值来自后端 `lowStockThreshold`，缺省 5）；
   水位条按 `sellable` 渲染；`data.lockedUnavailable=true` 时 `locked/sellable` 显示「—」并顶部告警，**不当作 0**。
3. **多规格 SKU 矩阵**：`src/views/goods/GoodsEditDialog.vue` — 规格维度（≤2）笛卡尔积生成矩阵，每组合占一行
   （如 颜色×尺码 = 4 行）；新建可编辑规格维度，编辑时规格项只读（原型「已有商品不可改规格项」）；
   `specValueIds` 由后端生成/校验：新建传值文本（D-02b 允许服务端翻译），编辑传 CI-32 返回的真 id。
4. **契约遵循 06/07/08**：金额一律分（`fen2yuan`/`money` 渲染），ID 全程字符串（不 `parseInt`）；
   状态文案优先用后端 `statusText`，本地 `constants/dict.js` 仅兜底；`data.errorCode` 由 `request.js` 统一提示。

## 3. 接口清单（全部 `/admin/**` 写操作；仅两处只读 C 端接口）

- 订单：`GET /admin/order/list`（CI-26）、`GET /admin/order/{id}`（CN-33）、`POST /admin/order/ship`（CI-27）、
  `POST /admin/order/close`（CN-10）、`POST /admin/order/update-ship`（CN-12）。已删除 `POST /admin/order/refund`（CX-02 下线）。
- 售后：`GET /admin/aftersale/list`（CN-01）、`GET /admin/aftersale/detail`（CN-02）、`approve`(CN-03)、`reject`(CN-04)、
  `confirm-receive`(CN-05)、`skip-receive`(CN-06)、`refund`(CN-07)、`retry-restock`(CN-08)、`close`(CN-09)。
- 商品：`GET /admin/goods/list`(CI-09)、`POST /admin/goods/create`(CI-10)、`PUT /admin/goods/update`(CI-11，带 `updateTime` 乐观锁)。
  **不提供删除**（D-05）。
- 库存：`GET /admin/stock/list`(CN-13)、`PUT /admin/stock/update`(CN-14，带 `expectNumber` 并发校验)。
- 评价：`GET /admin/comment/list`(CN-29)、`POST /admin/comment/reply`(CN-30)、`POST /admin/comment/status`(CN-31)。
- 工作台：`GET /admin/dashboard/stats`(CI-08，`period=today|7d|30d`)；低库存 KPI 取自 `CN-13?lowStockOnly=true&pageSize=1` 的 `total`。
- 只读参考：`GET /app/goods/detail`(CI-32)、`GET /app/goods/category`(CI-33)、`GET /app/goods/brand/list`(CI-34) —
  R1 无 admin 商品详情/分类/品牌端点，编辑弹层用它读取 `specifications/skus` 与分类树；写操作仍全部走 `/admin/**`。

## 4. 已知口径冲突与降级（需 R2/验收知悉）

1. **评价管理**：`03 §5.7` 标注 CN-29~31 属 R2「R1 不做」，但 `02 R1-07` 任务列与 captain 口径要求 R1 实现。
   本实现按任务/captain 落地（契约字段完整），接口未部署时页面捕获异常保持空态并提示，不刷错误。
2. **工作台 CI-08**：`08/03` 标为 R2 新增，本实现按任务要求落地：CI-08 字段优先，缺失时降级展示现状 4 字段
   （`goodsTotal/userTotal/todayOrders/undelivered`），KPI 缺失显示「—」，趋势图空态提示。
3. **商品编辑读详情**：R1 无 admin 详情端点，且 CI-32 对 `status∈{0,2}` 返回 404 `GOODS_OFF_SALE` →
   已下架/草稿商品**无法读取 SKU**；此时弹层顶部红提示，仅允许保存基础字段（不传 `skus`，避免误删规格）。
   建议 R2 补 admin 详情端点后切换。
4. **售后列表分页参数**：07 CN-01 写 `pageNo`，06 §3 统一 `pageNum`。已按 be-admin 约定只传 `pageNum`（后端保留 `pageNo` 别名）。
5. **售后状态出参口径**：契约要求标识串（`applied`/`refunding`…），实测 CN-01 列表返回数字码（`"0"`…`"7"`）。前端统一经 `aftersaleStatusKey()` 归一，`statusText` 优先展示，两种口径都能正确出标签与操作按钮。
