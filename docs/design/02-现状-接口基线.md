> 约束：**本次仅盘点和分析，未改动 `backend/**`、`frontend/**`、`prototype/**` 任何文件，未做 git 提交。**
> 依据：`backend/litemall-next/**` 源码 + `frontend/admin-web/src/api/**`、`frontend/mobile-web/src/api/**` 真实调用点 + `prototype/assets/**` 原型动作。
> 标注约定：**推断** = 由代码结构推得、未在运行态验证；**缺口** = 仓库内未发现；`文件:行` 中的 Java 路径均相对 `backend/litemall-next/`。

### 1.2 鉴权模型（现状）

| 层 | 事实 | 位置 |
| --- | --- | --- |
| 网关统一鉴权 | `AuthGlobalFilter implements GlobalFilter`，order=0 | `litemall-gateway/src/main/java/com/litemall/filter/AuthGlobalFilter.java:26,115-118` |
| 剥离伪造头 | 任何请求进网关先移除外部自带的 `user-info` 与 `X-Internal-Token` | 同上 `:41-45` |
| 免登录白名单 | `hm.auth.excludePaths` 精确匹配 | `AuthGlobalFilter.java:47,101-108`；清单见 `application.yaml:87-108` |
| 令牌校验 | `Authorization` 去 `Bearer ` 前缀 → `jwtTool.parseToken` → `checkRole` | `AuthGlobalFilter.java:52-64` |
| 角色/受众规则 | `/admin/**` → role=admin, aud=`litemall-admin`；`/app/**` → role=user, aud=`litemall-app` | `application.yaml:80-86` |
| 身份透传 | 校验通过后注入 `user-info` 头（下游 `UserContext` 读） | `AuthGlobalFilter.java:73-76` |
| 拒绝语义 | 401/403 **直接置 HTTP 状态码**（不返回 `Result` 体） | `AuthGlobalFilter.java:65-71,110-113` |
| 内部接口鉴权 | `/inner/**` 由 `InnerApiInterceptor` 校验 `X-Internal-Token`；非 dev 未配置密钥则启动失败（fail-fast）；dev 未配置时放行并 warn | `litemall-common-web/src/main/java/com/litemall/config/MvcConfig.java:30-34,41-45`；`litemall-common-web/src/main/java/com/litemall/interceptor/InnerApiInterceptor.java:15-52`；头名常量 `litemall-common-core/src/main/java/com/litemall/config/InnerApiProperties.java:19` |
| Feign 自动带内部头 | `FeignInnerConfig` 对所有经 `litemall-api` 的跨服务调用注入 `X-Internal-Token` | `litemall-api/src/main/java/com/litemall/config/FeignInnerConfig.java:13-28` |

**鉴权结论**：`/app/**` 默认需用户 JWT，`/admin/**` 默认需管理员 JWT，`/inner/**` 需内部共享密钥且不经网关；excludePaths 中的 16 条路径免登录（商品/营销浏览、登录注册、微信回调）。

## 4. 返回契约现状

### 4.1 `Result` 定义与成功码

| 事实 | 位置 |
| --- | --- |
| `public class Result<T> { int code; String msg; T data; }` | `litemall-common-core/src/main/java/com/litemall/domain/Result.java:8-11` |
| **成功码 = 200**：`ok(T)` → `new Result<>(200, "OK", data)` | 同上 `:17-19` |
| 通用失败 `error(String)` → **500** | 同上 `:21-23` |
| 指定码 `error(int, String)` | 同上 `:25-27` |
| 业务异常 `error(CommonException e)` → 用异常自带 code | 同上 `:29-31` |
| 成功判定方法 `success()` 为 `code == 200` | 同上 `:42-44` |

**结论：当前后端的成功码是 200，不是 0。** 仓库内不存在返回 `code=0` 的成功路径。

### 4.2 前端如何判成功

| 前端 | 判定 | 位置 | 备注 |
| --- | --- | --- | --- |
| `admin-web` | `if (res.code === 200) return res.data` | `frontend/admin-web/src/utils/request.js:19-25` | 注释明写「成功码只有 200（`Result.ok()`），后端不存在返回 0 的代码路径」（`:22`） |
| `admin-web` 业务码 401 | 登出 + 跳登录 | 同上 `:26-32` | |
| `admin-web` HTTP 层 | 401→登出、403→「无权访问」、其它→提示 | 同上 `:36-55` | 与网关「直接置 HTTP 状态码」对齐 |
| `mobile-web` | `if (res.code === 200) return res.data` | `frontend/mobile-web/src/utils/request.js:25-31` | 同上注释 `:28` |
| `mobile-web` HTTP 层 | 401/403/其它分流 | 同上 `:42-58` | |
| `prototype` | **不发 HTTP**：数据层为内存 + `localStorage`，写操作看 `Store.xxx()` 返回的 `{ok,msg}` | `prototype/assets/store.js:1-8`（文件头声明「纯前端，无任何服务端调用」）、`prototype/assets/README.md:155`（写操作一律看返回值） | 原型不参与 `Result` 契约 |
| 令牌注入 | 两侧都在请求头加 `Bearer <token>` | `admin-web/src/utils/request.js:13-15`；`mobile-web/src/utils/request.js:16-18` | 与网关 `AuthGlobalFilter.java:55-58` 的 `Bearer ` 剥离对应 |

### 4.3 仍按 `code===0` 判 / 硬编码状态码的位置

- **`code === 0` 判定：仓库内未发现**。`grep -rn "code *=== *0|code *== *0"` 在 `frontend/admin-web/src`、`frontend/mobile-web/src`、`prototype` 三处均为 0 命中（仅命中 `code === 200`：`admin-web/src/utils/request.js:23`、`mobile-web/src/utils/request.js:29`）。
- **硬编码状态码**：前端无 `status === 200`、无 `code: 200` 字面量；只有 `res.code === 200`、`response.status === 401/403` 三类判断（上表行号）。
- **契约不统一处（需注意，非遗留 bug）**：
  1. `/inner/**` 全部端点**不返回 `Result`**，直接返回业务对象/`void`/`PageVO`（如 `GoodsInnerController.java:56`、`MarketingInnerController.java:57`、`OrderInnerController.java:53`、`UserInnerController.java:40`、`MessageInnerController.java:29`）。Feign 客户端签名也按裸类型声明（`litemall-api/.../client/*.java`）。
  2. 5 个对外端点声明为**裸 `Result`（无泛型）**：`UserController.java:61`、`UserAddressController.java:31,46,54`。
  3. `GET /app/address/update` 的返回类型是 `Result<AddressDTO>`（`UserAddressController.java:38`），与其它「写操作返回 `Void`」不一致。
